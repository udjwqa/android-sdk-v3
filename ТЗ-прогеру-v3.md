# 🔥 ТЗ прогеру — SDK v3: ключи, кло, заливка (всё в одном)

Здесь ВСЁ что нужно: как воткнуть SDK v3 в APK, какие ключи по каждой приле, что совпадает с кло, дебаг-режим и чеклист перед заливом. Читай сверху вниз.

---

## 0. Что мы вообще делаем (на пальцах)

У каждой прилы в APK сидит тонкий клиент `AppClient.kt`. Он **не лезет напрямую к нашему скорингу** — стучится на «спортивный» **мини-сервер** (свой домен у каждой прилы), а тот уже спрашивает наш бэк (кло, он же «ложка»): это живой юзер или гугл/бот/модер?

- **живой юзер** → редирект на **оффер** (грязь);
- **бот / модер / гугл** → показываем **спортивную заглушку** (белая, чистая страница).

В APK **никакого палева** — только домен мини-сервера и пара параметров.

### Зачем v3, а не v2
В **v2** модер мог вытащить адрес запроса + токен прямо из APK и **долбить мини-сервер скриптом напрямую**, без всякой проверки телефона — и залетал на оффер. Дыра.

В **v3** оффер отдаётся **только после Play Integrity** — гугл сам подтверждает, что запрос с реального телефона (не эмуль/скрипт/ферма). Подделать нельзя. Вот это и чиним: **всё переводим на v3**.

Поток v3:
```
APK (AppClient) → мини-сервер (/path?sid=...&integrity_token=...) → кло /init → оффер ИЛИ заглушка
```

## 1. ЧАСТЬ ПРОГЕРА — воткнуть SDK v3 в APK

### 1.1 Зависимости (`app/build.gradle.kts`)
```kotlin
dependencies {
    implementation("com.squareup.okhttp3:okhttp:5.3.2")
    implementation("org.jetbrains.kotlinx:kotlinx-coroutines-android:1.11.0")
    implementation("com.google.android.play:integrity:1.6.0")          // Play Integrity
    implementation("androidx.browser:browser:1.8.0")                    // Chrome Custom Tabs
    // Push (обязательно для прохождения модерации)
    implementation(platform("com.google.firebase:firebase-bom:34.13.0"))
    implementation("com.google.firebase:firebase-messaging")
    implementation("com.google.firebase:firebase-crashlytics")
}
```
Плагин Crashlytics: в корневом `build.gradle.kts` → `id("com.google.firebase.crashlytics") version "3.0.3" apply false`, в `app` → `id("com.google.firebase.crashlytics")`.

### 1.2 Скопировать `AppClient.kt`
Берёшь файл `AppClient.kt` из этого репо, кидаешь в проект. Пакет можно переименовать как удобно.

### 1.3 Инициализация в Application
```kotlin
class MyApp : Application() {
    lateinit var appClient: AppClient; private set
    override fun onCreate() {
        super.onCreate()
        appClient = AppClient(
            context = this,
            endpoint = "https://ТВОЙ-ДОМЕН",      // см. таблицу ключей (часть 2)
            path = "/твой_путь",                  // см. таблицу
            authToken = "ТВОЙ_SID",               // см. таблицу (это authToken/sid)
            enableIntegrity = !BuildConfig.DEBUG, // release: PI вкл, debug: выкл
        )
    }
}
```

### 1.4 Получить URL при старте
```kotlin
lifecycleScope.launch {
    val url = (application as MyApp).appClient.resolve()
    if (url.isNotEmpty()) {
        openUrl(url)        // серый или белый — решает сервер
    } else {
        showMainContent()   // сервер недоступен → нативный контент
    }
}
```

### 1.5 Открыть URL — Chrome Custom Tabs (предпочтительно)
```kotlin
val intent = androidx.browser.customtabs.CustomTabsIntent.Builder().build()
intent.launchUrl(context, android.net.Uri.parse(url))
```
WebView — только если без него никак. Тогда:
```kotlin
webView.settings.apply {
    javaScriptEnabled = true
    domStorageEnabled = true
    allowFileAccess = false
    mixedContentMode = WebSettings.MIXED_CONTENT_NEVER_ALLOW
}
webView.loadUrl(url)
```
> ❌ НИКОГДА: `addJavascriptInterface`, `evaluateJavascript` — это бан-палево.

### 1.6 Обязательно ещё
- **Offline:** `WebViewClient.onReceivedError` (main frame) → спрятать webview, показать нативный «нет сети».
- **Back:** `onBackPressedDispatcher` → `webView.goBack()` / `finish()`.
- **Push:** `FirebaseMessagingService.onMessageReceived` + сервис в манифесте.
- **ProGuard:** `-dontwarn okhttp3.**` / `-dontwarn okio.**`.

### 1.7 Что SDK реально шлёт на сервер
```
https://домен/path?app_id=com.pkg&locale=it&app_version=1.0&instance_id=uuid&sid=ТОКЕН&integrity_token=XYZ
```
Всё стандартное: пакет, язык, версия, UUID установки, токен авторизации, PI-токен. Ни модели, ни GPU, ни кастомных X-заголовков — **это и есть «чистота» v3**.

## 4. DEBUG / ТЕСТ-РЕЖИМ (читать ПЕРЕД тестом, иначе будешь рвать волосы)

В debug-сборке `enableIntegrity = !BuildConfig.DEBUG` = **false** → SDK **не шлёт PI-токен**. А сервер настроен «нет токена = не пускать» → отдаёт **белую заглушку**. **Это не баг.** В дебаге ты по умолчанию **всегда видишь белое**.

Чтобы потестить оффер на своём девайсе с дебаг-сборкой:
1. Панель → **Настройки** → блок **«Debug / тест-режим»**.
2. Впиши свой тестовый **IP** или **instance_id** (instance_id видно в деталях клика в дашборде).
3. Сохрани → с этого IP/instance запросы идут в обычный скоринг → на чистом девайсе получишь **оффер**.
4. **После теста — очисти список!**

> ⚠️ НЕ проси выключить `require_integrity` на сервере ради теста — это открывает дыру модерам. Только whitelist.
> В **release** `enableIntegrity = true` — PI пашет штатно, ничего не трогаешь.

## 5. ЧТО НЕЛЬЗЯ (палево = бан)

- ❌ `addJavascriptInterface`, `evaluateJavascript`
- ❌ собирать GPU / codename / build product / модель — это фингерпринтинг
- ❌ кастомные X-заголовки (`X-Client-Secret`, `X-Device-Info` и т.п.) — это привычки v2, в v3 НЕ нужно
- ❌ `isEmulator()` / `isRooted()` в коде прилы
- ❌ сканить установленные приложения
- ❌ хардкодить домен бэка (кло) — в APK только домен мини-сервера
- ❌ палевные строки в DEX: `casino`, `bet`, `verdict`, `cloak` и пр.
